# 会话连续性与用户账号白名单

## 管理配置

在「用户 → 分组配置 → 可用账号」选择分组，再独立保存账号策略。该配置对用户的所有 API Key 生效，不授予分组访问权。

- 不限制：使用已有分组范围和调度规则。
- 指定账号：只从所选账号中选择，选择一个账号即可固定账号。
- 指定账号且名单为空：禁止访问，不恢复为全组可用。
- 删除、移出分组或停用账号：相应账号不可使用，限制标记保留。
- 降级和内部跨分组路由：保留原分组约束，同时检查目标分组策略。

管理员接口：GET /api/v1/admin/users/:id/groups/:group_id/account-policy 和 PUT 同一路径。
请求和响应的数据结构为 mode（all 或 allowlist）与 account_ids（账号 ID 数组）。all 必须配空数组；allowlist 允许空数组；保存时校验账号属于分组。

策略保存成功后失效该用户认证缓存。选号、发送前及 WebSocket 后续轮次读取当前策略；当前已发出的响应可完成。数据库不可用时拒绝请求，避免权限检查失效后放行。

## OpenAI / Codex 连续性

历史响应归属优先于会话绑定；已有绑定优先于新会话评分。容量不足进入现有队列和等待预算，短暂冷却等待恢复。临时失败保留原绑定。容量等待超时后，请求上下文完整且不依赖历史 ID 时，至多重选一次获准账号；其余情况返回可重试错误。

路由按用户、分组隔离；明确会话标识优先，内容推导作为兜底。内容兜底路由不因模型变化而改变；上游缓存标识维持原有规则。旧绑定仅作为经过当前授权、分组和账号状态校验的迁移提示。

prompt_cache_key 是上游缓存提示，不作为优先会话身份。账号路由优先使用明确会话头、Codex 线程信息、请求体 client_metadata / metadata 中的 session_id 或 conversation_id；没有明确标识时使用包含首条用户输入的内容兜底，并忽略模型变化。因此同一线程或完整历史请求即使缓存键变化，也不会重新评分换号。客户端传入的缓存键以及已有上游账号隔离规则保持不变。

WebSocket 在连接内保留首轮路由，后续增量输入和缓存键变化不会更换身份；缺少明确身份的独立连接使用不同兜底标识，避免同用户所有会话被绑定成一个会话。缓存键不再参与 OpenAI 的连接抢占作用域。HTTP 若只携带不断变化的缓存键和当轮增量文本，且没有会话/线程标识或可恢复的历史响应归属，服务端无法可靠判断它们属于同一会话；应由客户端传入稳定会话标识，不通过用户级全局绑定猜测关联。

只有请求自身不依赖上游历史状态，或当前 WebSocket 已收集完整的响应历史链且引用可迁移时，才允许重放到其他账号。仅有工具调用配对无法证明聊天历史完整。历史 ID、文件引用、加密内容等无法证明可恢复时拒绝迁移；不会删除历史 ID 后静默继续。已经输出的轮次不自动跨账号重放。

Redis 会话占用与版本校验约束并发选号和绑定提交。只在成功响应后提交新绑定，失败和迟到结果不能覆盖较新的绑定。HTTP、WebSocket 原生、桥接和透传均执行授权检查；透传模式保留自己的上游状态，缺少完整本地重放历史时要求客户端重连重试。

常见错误：ACCOUNT_ACCESS_DENIED（403）、SESSION_CONTEXT_INCOMPLETE（409）、SESSION_ACCOUNT_UNAVAILABLE / ALLOWED_ACCOUNTS_UNAVAILABLE / ACCOUNT_POLICY_UNAVAILABLE（503）。WebSocket 使用相应策略拒绝或可重试关闭原因。

## 会话恢复与使用记录追踪

管理员在「使用记录 → 明细」中可以查看、复制会话 ID，点击 ID 或输入完整 ID 精确筛选。
会话筛选与日期、用户、账号等筛选条件取交集；需要查看完整历史时请扩大日期范围。
明细、统计卡片、趋势、模型/分组分布和 Excel 导出都沿用会话筛选。
没有显式客户端会话标识的历史记录显示 `-`，不根据时间或模型猜测归属。
会话 ID 由客户端提供，不是全局唯一或身份凭证；不同用户复用 ID 时请同时筛选用户。
缓存读取/写入 token 和费用来自每条上游用量记录；同一会话不保证共享上游缓存。
使用记录展示实际记录用量的请求，不是失败重试的完整审计日志，失败尝试仍需查看错误日志。

### OpenAI Responses HTTP 会话恢复

带显式客户端会话 ID 的普通 OpenAI 账号，在尚未输出实际响应内容时遇到可重试的
500/502/503/504 上游故障，会先在原账号最多额外重试两次（0.5 秒、1 秒退避）。
已有池模式、凭据故障、首输出超时、限流等专门策略保留各自边界。
每次重试仍重新核对账号权限、状态、模型和并发容量；失效或撤销权限的账号不会被强行使用。

原账号重试耗尽后，完整且可迁移的请求可在用户允许的账号范围内自动换号，
成功完成后才更新会话绑定。不会为了换号删除加密推理内容、工具结果或历史引用。
如果请求依赖 `previous_response_id`，返回 `SESSION_ACCOUNT_UNAVAILABLE`（503）；
如果含不可迁移状态或历史不全，返回 `SESSION_CONTEXT_INCOMPLETE`（409）。
已经开始输出或客户端已断开时不自动重放；SSE 已提交响应头时通过流内错误结束。
WebSocket 和其他协议保留现有恢复策略。

新增迁移 `242_add_usage_log_session_id_index_notx.sql` 为精确会话查询建立并发索引，
不改写历史迁移、不改变业务数据。上线仍按仓库部署流程执行。
