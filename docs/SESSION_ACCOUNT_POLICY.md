# 会话连续性与用户账号白名单

## 管理配置

在「用户 → 分组配置 → 可用账号」选择分组，再独立保存账号策略。该配置对用户的所有 API Key 生效，不授予分组访问权。

- 不限制：使用已有分组范围和调度规则。
- 指定账号：只从所选账号中选择，选择一个账号即可固定账号。
- 指定账号且名单为空：禁止访问，不恢复为全组可用。
- 删除、移出分组或停用账号：相应账号不可使用，限制标记保留。
- 降级和内部跨分组路由：保留原分组约束，同时检查目标分组策略。

管理员接口：GET /api/v1/admin/users/:id/groups/:group_id/account-policy 和 PUT 同一路径。
请求和响应的数据结构为 mode（all 或 allowlist）与 account_ids（账号 ID 数组）。all 必须配空数组；allowlist 允许空数组；保存时校验账号属于分组。

策略保存成功后失效该用户认证缓存。选号、发送前及 WebSocket 后续轮次读取当前策略；当前已发出的响应可完成。数据库不可用时拒绝请求，避免权限检查失效后放行。

## OpenAI / Codex 连续性

历史响应归属优先于会话绑定；已有绑定优先于新会话评分。容量不足进入现有队列和等待预算，短暂冷却等待恢复。临时失败保留原绑定。容量等待超时后，请求上下文完整且不依赖历史 ID 时，至多重选一次获准账号；其余情况返回可重试错误。

路由按用户、分组隔离；明确会话标识优先，内容推导作为兜底。内容兜底路由不因模型变化而改变；上游缓存标识维持原有规则。旧绑定仅作为经过当前授权、分组和账号状态校验的迁移提示。

prompt_cache_key 是上游缓存提示，不作为优先会话身份。账号路由优先使用明确会话头、Codex 线程信息、请求体 client_metadata / metadata 中的 session_id 或 conversation_id；没有明确标识时使用包含首条用户输入的内容兜底，并忽略模型变化。因此同一线程或完整历史请求即使缓存键变化，也不会重新评分换号。客户端传入的缓存键以及已有上游账号隔离规则保持不变。

WebSocket 在连接内保留首轮路由，后续增量输入和缓存键变化不会更换身份；缺少明确身份的独立连接使用不同兜底标识，避免同用户所有会话被绑定成一个会话。缓存键不再参与 OpenAI 的连接抢占作用域。HTTP 若只携带不断变化的缓存键和当轮增量文本，且没有会话/线程标识或可恢复的历史响应归属，服务端无法可靠判断它们属于同一会话；应由客户端传入稳定会话标识，不通过用户级全局绑定猜测关联。

只有请求自身不依赖上游历史状态，或当前 WebSocket 已收集完整的响应历史链且引用可迁移时，才允许重放到其他账号。仅有工具调用配对无法证明聊天历史完整。历史 ID、文件引用、加密内容等无法证明可恢复时拒绝迁移；不会删除历史 ID 后静默继续。已经输出的轮次不自动跨账号重放。

已认证 OpenAI 会话的归属、占用与提交版本保存在 PostgreSQL；Redis 保存兼容缓存。只在成功响应后提交新绑定，失败和迟到结果不能覆盖较新的绑定。HTTP、WebSocket 原生、桥接和透传均执行授权检查；透传模式保留自己的上游状态，缺少完整本地重放历史时要求客户端重连重试。

常见错误：ACCOUNT_ACCESS_DENIED（403）、SESSION_CONTEXT_INCOMPLETE（409）、SESSION_ACCOUNT_UNAVAILABLE / ALLOWED_ACCOUNTS_UNAVAILABLE / ACCOUNT_POLICY_UNAVAILABLE（503）。WebSocket 使用相应策略拒绝或可重试关闭原因。

## 会话恢复与使用记录追踪

管理员在「使用记录 → 明细」中可以查看、复制会话 ID，点击 ID 或输入完整 ID 精确筛选。
会话筛选与日期、用户、账号等筛选条件取交集；需要查看完整历史时请扩大日期范围。
明细、统计卡片、趋势、模型/分组分布和 Excel 导出都沿用会话筛选。
没有显式客户端会话标识的历史记录显示 `-`，不根据时间或模型猜测归属。
会话 ID 由客户端提供，不是全局唯一或身份凭证；不同用户复用 ID 时请同时筛选用户。
缓存读取/写入 token 和费用来自每条上游用量记录；同一会话不保证共享上游缓存。
使用记录展示实际记录用量的请求，不是失败重试的完整审计日志，失败尝试仍需查看错误日志。

### OpenAI Responses HTTP 会话恢复

带显式客户端会话 ID 的普通 OpenAI 账号，在尚未输出实际响应内容时遇到可重试的
500/502/503/504 上游故障，会先在原账号最多额外重试两次（0.5 秒、1 秒退避）。
已有池模式、凭据故障、首输出超时、限流等专门策略保留各自边界。
每次重试仍重新核对账号权限、状态、模型和并发容量；失效或撤销权限的账号不会被强行使用。

原账号重试耗尽后，完整且可迁移的请求可在用户允许的账号范围内自动换号，
成功完成后才更新会话绑定。工具结果和历史引用不删除；普通 Responses HTTP 对辅助推理密文
的有限降级见下文“Responses HTTP 均衡恢复”。
如果请求依赖 `previous_response_id`，返回 `SESSION_ACCOUNT_UNAVAILABLE`（503）；
如果含不可迁移状态或历史不全，返回细分的 `LOCAL_SESSION_*`（409），内部仍保留
`SESSION_CONTEXT_INCOMPLETE` 基础错误用于兼容判断。
已经开始输出或客户端已断开时不自动重放；SSE 已提交响应头时通过流内错误结束。
WebSocket 和其他协议保留现有恢复策略。

### 409 拒绝诊断

`SESSION_CONTEXT_INCOMPLETE` 的各拒绝分支输出 WARN 事件
`openai.session_context_incomplete`，沿用请求日志中的 `request_id` 和
`client_request_id`。`reason` 区分响应归属缺失、会话标识缺失、绑定缺失、
绑定账号不可选、重试后无法迁移，以及协议转换无法续接等情况；已知账号时记录
`account_id`。`session_hash` 可关联 Redis 中的会话绑定，但不输出原始会话 ID。
`previous_response_present`、`migration_unsafe` 和 `non_portable_reason`
记录有无前序响应引用、能否迁移及第一个不可迁移原因，不保存正文、工具结果、
加密内容、文件 ID 或凭据。`bound_account_not_selectable` 只表明原账号未被选中，
并不单独证明是冷却、模型不兼容还是并发等具体限制。

该诊断需随新镜像上线才生效，不能补回旧请求未保存的请求体、会话标识或历史绑定。

新增迁移 `242_add_usage_log_session_id_index_notx.sql` 为精确会话查询建立并发索引，
不改写历史迁移、不改变业务数据。上线仍按仓库部署流程执行。

### 会话绑定持久化与 Redis 过期恢复

迁移 `243_openai_session_bindings.sql` 新增按用户、分组和路由哈希隔离的会话归属表，
不修改已有表和历史迁移，不保存聊天正文、加密内容、凭据或原始会话 ID。
成功确认的账号归属不设 TTL；用户被物理删除时级联删除归属。账号删除不会抹去原归属，
避免把无法使用的旧账号误当成从未绑定过的新会话。

24 小时 Redis 会话 TTL 仍在成功提交时续期，但缓存过期、淘汰或重启不再决定已持久化
会话的寿命。数据库归属优先于 Redis 和用量历史，读取故障返回可重试错误，不猜测账号。
30 秒占用租约独立于归属寿命，每 10 秒续租；租约失效或较新请求取得占用后，旧请求
不能提交归属，即使 Redis 被清空也不能绕过这一校验。

升级前尚无持久化记录的会话，优先读取同用户的 Redis 绑定；绑定缺失时，仅使用与
当前路由身份一致的显式 `session-id` / `session_id` 头查询用量记录，并同时匹配用户
和分组。按时间及 ID 取最近一条记录的账号作为恢复候选；用量记录可能包含未完整成功
的请求，因此查到候选不等于上游已经恢复，也不会直接写入持久化绑定。
不使用其他用户共享的旧缓存键，不根据时间、模型、相邻会话猜测身份，也不向更早记录
逐个试号。旧历史没有显式 ID、已清理或身份不匹配时，不承诺恢复。

恢复候选仍经过当前白名单、账号状态、分组、模型、冷却及并发限制检查。携带加密内容
的请求优先尝试原账号；仅在下文均衡恢复的结构校验通过时允许有限降级。只有上游实际成功后才提交
并刷新 Redis 镜像。`session_binding_recovery_candidate` 日志只记录用户、分组、账号 ID。

此处持久化的是会话到账号的归属，不是上游对话内容。`previous_response_id` 的独立归属
及 HTTP 响应所有者记录仍使用原有响应 TTL；WebSocket 活连接和进程内重放状态也不被
数据库重建。上游已经删除历史、密文失效或仅靠过期响应 ID 续接的请求仍可能无法恢复。

新增回归覆盖 Redis TTL/清空/断连、进程重建、陈旧缓存、数据库故障、过期租约、并发
恢复、迟到提交、历史用户/分组隔离，以及恢复后的撤权和不可调度保护。

### Responses HTTP 均衡恢复

普通 OpenAI Responses HTTP 请求启用均衡恢复，压缩请求、生图和 WebSocket 保留原有策略。
原账号正常时原样保留推理密文；原账号短暂冷却最多等待 8 秒，明确超过恢复窗口的冷却
不空等。并发等待也受 8 秒上限约束。原有上游超时仍然生效；8 秒不是整个生成请求的超时。

只有请求不带 previous_response_id / conversation，输入从可读用户消息开始、包含历史
助手消息或已完成的工具调用，而且工具调用与结果按 ID 完整配对，才允许在原渠道不可用时
删除辅助 reasoning 密文条目并在备用渠道重放。其余消息、工具参数和结果保持不变。
这属于结构检查，不能证明客户端没有省略普通消息；不会从服务端存储重建正文。
压缩历史 compaction、文件/容器/向量库/条目引用、未完成工具调用和未知输入类型不能使用
这条降级路径。仅删除密文无法恢复压缩掉的内容，因此不能这么处理 compaction。

每个请求最多尝试一个备用账号（同账号的既有有界重试仍适用），成功后才提交新归属。
备用账号失败不会继续逐个试号；本轮已输出实际内容或客户端已断开时不自动重放。
历史归属缺失但请求满足上述结构检查时，也只允许一次恢复尝试。权限和模型等调度条件
始终生效；去掉隐藏推理可能影响连贯性和缓存命中，但不会主动删除可见消息或工具结果。

HTTP 请求的租约由 handler 生命周期收尾，成功提交之前不会仅因客户端收到终止事件后
断开而提前释放；失败请求结束仍释放占用，不确认新的归属。数据库租约到期、存储故障或
较新请求取得租约后，迟到请求仍不能覆盖新归属。

对客提示优先中文，稳定 code 保留英文供程序判断。会话错误 type 区分
local_validation_error（本地历史/资源校验）、local_permission_error（本地权限）、
local_state_error（本地存储/租约）、local_routing_error（本地路由/恢复预算）。
具体 code 包括 LOCAL_SESSION_BINDING_MISSING、LOCAL_RESPONSE_OWNER_MISSING、
LOCAL_SESSION_ENCRYPTED_HISTORY、LOCAL_SESSION_COMPACTED_HISTORY、
LOCAL_SESSION_TOOL_CONTEXT_MISSING、LOCAL_SESSION_RESOURCE_BOUND、
LOCAL_SESSION_STORE_UNAVAILABLE、LOCAL_SESSION_LEASE_LOST、LOCAL_SESSION_RECOVERY_EXHAUSTED。
上游通用错误使用 UPSTREAM_AUTHENTICATION_FAILED / UPSTREAM_ACCESS_FORBIDDEN /
UPSTREAM_RATE_LIMITED / UPSTREAM_OVERLOADED / UPSTREAM_UNAVAILABLE / UPSTREAM_REQUEST_FAILED。
标准 upstream_error、rate_limit_error 等类型继续兼容客户端；code 可区分本地和上游限流。
普通 JSON 与 response.failed SSE 均携带 code；Ops 保留最终本地拒绝的归因，并附带此前
实际发生的上游失败尝试。第三方原始错误和管理员自定义透传提示不强行翻译。

本阶段不保存聊天正文、不新增数据库迁移；依赖前一版的 243 会话归属迁移。
