# OpenAI 会话连续性

HTTP Responses（含 compact）使用“用户＋分组＋稳定会话标识＋客户端请求模型”
作为渠道绑定、请求租约和加密恢复检查点的范围。模型使用完整名称，不按等级或
家族合并；上游模型映射、推理强度和 prompt cache key 不改变已建立的模型范围。
例如同一会话的 Astra 请求绑定渠道 A，委派的 Luna 请求绑定渠道 B，后续 Astra
请求继续使用 A。只有成功完成的请求才能更新自身模型的绑定。

升级后的首次请求可按用户、分组、会话以及 requested_model 查询该模型最后一次
成功用量，恢复旧会话的候选渠道。旧记录没有 requested_model 时使用 model。
候选仍须通过当前权限和调度检查，不能使用另一模型的最后一次请求代替。
旧检查点仅用于只读恢复，仍要求压缩条目的密文摘要及历史窗口精确匹配；新
检查点写入新的模型范围，无需修改数据库结构或覆盖旧绑定。

原渠道故障时，已有的限次切换机制只处理可验证的完整历史。additional_tools
和 configuration_update 属于明确的工具声明和推理设置，保留其内容和历史位置。
缺失工具结果、未匹配的压缩历史或资源引用仍不能通过删除密文强行接续。

上述模型范围用于 HTTP Responses；WebSocket 的连接状态仍遵循原有连接隔离与
响应所有权检查。本次不调整计费、客户端缓存键、模型映射或账户权限。
